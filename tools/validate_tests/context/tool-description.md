Ask the operator to validate the tests written for the current task before any production code is written. Call it right after writing the tests, with a one-line `task`, the `scope` and functional guidelines the tests define, the list of behaviours they cover (`cases`) and optionally the `testFiles`. The operator either validates the tests or asks for rework with feedback. Only start development when `status` is "validated"; on "rework", change the tests according to the feedback and call this tool again; on any other status, stop and ask the operator how to proceed.
