Demande à l'opérateur de valider les tests écrits pour la tâche en cours, avant tout code de production. L'agent DOIT appeler cet outil dès que les tests sont écrits, avec la tâche en une ligne (`task`), la portée et les exigences fonctionnelles définies par les tests (`scope`) et la liste des comportements couverts (`cases`) ; la liste des fichiers de tests (`testFiles`) est OPTIONNELLE. L'opérateur valide les tests ou demande une reprise avec ses retours. L'agent NE DOIT PAS commencer le développement tant que `status` ne vaut pas "validated". Si `status` vaut "rework", l'agent DOIT modifier les tests selon `feedback` puis DOIT rappeler cet outil. Pour tout autre `status`, l'agent DOIT s'arrêter et demander à l'opérateur comment procéder. Les mots-clés en majuscules s'interprètent selon le BCP 14 [RFC 2119] [RFC 8174].
