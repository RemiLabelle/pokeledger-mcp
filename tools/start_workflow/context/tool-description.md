Renvoie les règles de travail OBLIGATOIRES pour toute tâche de code de ce projet : terminologie BCP 14, cadence de versionnage, conventions Git, workflow TDD, décisions d'implémentation et langue des commentaires. L'agent DOIT appeler cet outil avant de commencer une tâche de code et DOIT appliquer les règles renvoyées pendant toute la tâche. Le paramètre `sections` est OPTIONNEL : il PEUT contenir des identifiants comme "terminology", "versioning", "git", "tdd", "governance", "decisions", "forms", "skills" ou "comments" pour ne renvoyer qu'une partie des règles. Les paramètres `step` et `input` sont OPTIONNELS : avec `step`, l'outil exécute l'étape interne nommée (validation des tests, choix ou confirmation d'implémentation) avec `input` au lieu de renvoyer les règles ; la description de `step` documente chaque étape et son `input`. Au premier chargement des règles de la session, l'outil demande à l'opérateur si l'agent doit versionner automatiquement ; en cas de refus, il renvoie un avertissement majeur qui a priorité sur les règles de versionnage. Le paramètre `autoVersioning` est OPTIONNEL : l'agent NE DOIT le renseigner qu'avec une réponse explicite de l'opérateur, lorsque les règles renvoyées lui demandent de la recueillir dans la conversation.
