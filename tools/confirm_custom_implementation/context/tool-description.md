Signale à l'opérateur les problèmes de son implémentation personnalisée et lui demande s'il maintient son choix en connaissance de cause. L'agent DOIT lancer cette étape, après l'étape `choose_implementation`, lorsque l'implémentation proposée par l'opérateur ne s'aligne pas sur le code existant ou introduit une mauvaise odeur de code ou un anti-patron. L'agent DOIT fournir dans `input` la décision (`decision`), l'implémentation de l'opérateur (`custom`) et la liste précise des problèmes (`problems`). Si `status` vaut "proceed", l'agent DOIT implémenter le choix de l'opérateur tel quel, sans le réévaluer. Si `status` vaut "cancelled", l'agent DOIT relancer l'étape `choose_implementation` avec les mêmes options. Pour tout autre `status`, l'agent DOIT s'arrêter et demander à l'opérateur comment procéder. Les mots-clés en majuscules s'interprètent selon le BCP 14 [RFC 2119] [RFC 8174].
